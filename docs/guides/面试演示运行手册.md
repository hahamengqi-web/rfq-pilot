# NanoClaw 面试演示运行手册

## 一键启动

在项目根目录执行：

```powershell
.\scripts\start_demo.ps1
```

默认使用固定演示数据，外部搜索、地图、海关、新闻和报告模型不会拖慢现场演示。页面会明确显示“演示模式”。
固定演示模式还会暂停真实 QQ 等邮箱的自动收件；账户和授权码配置保留。要恢复自动收件，请退出固定演示模式并重启应用。
脚本会先结束占用演示端口的旧 NanoClaw 进程，等待 MySQL、Redis、Milvus、Elasticsearch、RAG 和两个页面全部就绪，再预热客户门户的 Archer AX55 示例问题。任一关键检查失败都会停止并显示原因，不会在服务半就绪时提示成功。

需要展示真实接口优先、失败后自动降级时执行：

```powershell
.\scripts\start_demo.ps1 -UseRealExternalServices
```

面试现场建议使用默认命令。真实接口模式用于单独展示外部工具接入，会受到网络延迟、第三方限流和账户积分影响。

## 演示前检查

```powershell
.\scripts\demo_doctor.ps1
```

全部显示“通过”后再开始演示。检查脚本不会输出任何密钥。

## 固定演示流程

1. 打开客户智能客服 `http://127.0.0.1:8766/`，询问 Archer AX55 的 LAN 口、使用场景或售后问题。
2. 打开内部工作台 `http://127.0.0.1:8767/`，展示 RAG 文档、父子块和人工客服工单。
3. 在询盘工作流点击“创建新的演示询盘”。系统会从 `examples/demo/northstar-inquiry.eml` 建立一条独立的新案例，列表默认只显示固定演示案例；“查看全部历史”可查看其他询盘。
4. 在“待核实询盘”确认样例邮件里的公司官网 `https://northstar-retail.example`、柏林地址和注册编号 `HRB-DEMO-2026`，保存后展示 RFQ 字段提取、Plan-and-Execute 调查计划、官网/地图/海关/新闻步骤。
5. 打开背调报告。演示结果会带有醒目标记，不会冒充真实调查结果。
6. 人工确认背调，并在审批说明中写明本地调查资料仅供演示。进入报价准备后，录入演示销售条件：`DEMO-AX55-EU`、50 件、单价 85 USD、FOB Shanghai，四项费用填 0，有效期选择未来日期。展示回复 Agent 的受限计划和待审批草稿；金额 4,250 USD 由报价计算工具生成。
7. 在邮件草稿中修改主题或正文并保存，系统会创建新版本并要求重新审批。
8. 审批后案例应进入“等待客户回复”，交付记录状态为 `demo_accepted`，模拟邮件保存到 `runtime/demo-mailbox`；它是本地 `.eml` 文件，不会发给真实客户。

## 停止应用

```powershell
.\scripts\stop_demo.ps1
```

该命令只停止 NanoClaw 应用进程，保留数据库容器和数据，方便下一次快速启动。
